# Variable request context evaluation brief

Use the public Ritween skill and installed public APIs only. Produce a six-second
960×720 request-diagnostics explainer with compact, expanded incident and recovery
states. Use variable query/status rows, 3:1 weighted flexible slots beside an intrinsic
button, padded content-sized cards, a longer paragraph that changes card height,
explicit safe areas, and fractional scrolling inside a stationary clipped viewport.
Use deterministic licensed fonts preloaded for every conditional state. Keep stable
scoped IDs and enumerate content variants, motion boundaries and rule samples before
coding. Do not deep-import source, use internal globals or replace the renderer.

## Shared assertions (do not change between modes)

- Public imports and strict type consumer compile against package declarations.
- All seven example rules pass at all eleven authored samples; no indeterminate,
  failure, empty applicable coverage or missing targets. Inspect diagnostics separately.
- Cards have no duplicated fixed background heights; expanded copy changes card height.
- Weighted query/status slots have ratio 3:1; gaps at least 16, card gap 24, inset 24.
- Local and stationary-output safety are distinct; scroll viewport position/size stays
  fixed within each content state while event paint moves at fractional positions.
- Verify actual loaded primary family/weights, not fonts.check alone. Record browser,
  GPU, output, package, font/license hashes and project/rules identity.
- Capture every state/boundary and contact sheet. Review hierarchy, readability,
  density, contrast and optical alignment; report reviewer identity and human status.
- Calibrate unchanged renders, then use one renderer for forward/backward A/B/A;
  repeated A geometry/pixels match, B differs and demonstrates actual motion.
- Actual public CLI inspect/rules/frame/export runs in local and isolated installed
  modes use the same caller project, brief, skill, arguments and expected outcomes.
  Export only after failures fixed or explicit named operator exception.
- Malformed rules exit 2 without destroying old output; requested rule failure exits 1.
  Record counts/exits and measured vs subjective vs unsupported results separately.

## Agent trial protocol

Only when separately authorized, run at least three baseline and three candidate
independent agent trials with identical model/settings, brief, skill inputs and
assertions across CLI modes. Preserve baseline identity rather than inventing trials
from unrelated history. Record every failure, repair iteration, geometry outcome and
visual review. Deterministic consumer checks are not independent agent trials and do
not establish general reliability. If launches are unavailable/unauthorized, mark
agent reliability UNVERIFIED and obtain operator approval before any reliability claim.
